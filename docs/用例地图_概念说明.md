# 用例地图：概念说明（汇报提纲答复）

---

## 1. 一句话定义：什么是用例地图

**用例地图**是以业务领域真实逻辑（流程节点 / 状态机 / 字段 / 规则）为骨架，把历史用例与缺口用例精准挂载上去，形成可检索、可评审、可追溯、可演进的**测试知识图谱**——不是平铺的用例列表，而是「业务依据 ↔ 测试资产」的双向地图。

### 2.1 节点（Node）

| 节点类型 | 含义 | 本案例真实示例 |

### 2.2 边（Edge）

| 边类型 | 连接 | 本案例真实连接 |
|---|---|---|
| 归属边 | 用例 → 流程节点 | TC-QUOTE-001 → 报价单生成 |
| 依据边 | 用例 → 状态/字段/规则 | TC-QUOTE-088 → R002、totalPrice |
| 上下游边 | 流程节点 ↔ 流程节点 | 设计方案 → 报价 → 签约 |

| 版本边 | 用例 ↔ 版本 | TC-QUOTE-088@v3 ACTIVE |
| 追溯边 | 节点 → 多层级关联用例 | 造价审核 → 状态依据 → 关联用例 |

### 2.3 关系（Relationship）约束要点

- 四层主结构：**领域 → 流程节点 → 测试依据 → 用例资产**（禁止只靠平铺列表作为主视图）
- 挂载带**置信度**：≥80 自动挂载；60–79 抽检；&lt;60 人工确认
- 正式入库用例至少绑定一种测试依据
- 同一 `caseId` 同时仅允许一个生效版本（ACTIVE）
- 已废弃用例不可作为新回归包正式基线

## 3. 用途是什么，解决了哪些场景的哪些问题

### 3.1 核心用途

1. **看清业务**：按领域/节点展示端到端链路与上下游  
2. **盘活资产**：历史用例重挂载，避免模块错位导致的“沉睡用例”  
3. **说清缺口**：用状态/字段/规则矩阵量化盲区  
4. **稳住回归**：按节点沉淀核心回归集  
5. **支撑运营**：需求推荐、版本回归圈选、自动化候选输出  

### 3.2 场景 × 问题

| 场景 | 解决的问题 |
|---|---|
| 新需求测试 | PRD 模糊/缺失时，难定测试边界与范围 → 按变更节点推荐用例并提示缺口 |
| 版本回归 | 回归范围靠经验、过大或过小 → 按核心节点拉取最小高价值回归包 |
| 覆盖治理 | 不知道测全了没有 → 三维覆盖矩阵量化盲区并生成缺口用例 |
| 自动化建设 | 不知道先自动化什么 → 优先输出高风险、稳定、可接口化候选 |
| 多领域推广 | 每个领域从零建设成本高 → 配置化复制（换节点/状态/规则即可） |
| 资产检索与追溯 | 找不到、追不到关联用例 → 关键词/场景/应用/接口/上下游/多层级追溯 |

## 4. 现状、挑战是什么

### 4.1 现状（痛点）

1. **历史用例沉淀混乱**：模块归属错位、粒度不一、检索难、复用率低  
2. **需求资产缺失**：PRD/原型未系统归档，难还原功能边界，易漏测  
3. **代码资产未纳入**：真实业务逻辑在代码/知识库中，却未成为测试设计基准  

### 4.2 挑战

1. 历史用例原模块标签不可信，需重挂载且保留置信度  
2. **知识库准度待验**：开发知识库返回的状态机/字段/规则可能偏离真实代码，需对照代码复核后才能作为地图骨架  
3. **历史复用不足**：存量用例粒度与表述参差，可直接复用比例偏低，多数需人工确认后再生成或改写  
4. **变更难以及时同步**：新需求迭代与代码更新后，地图缺少增量感知与自动重算，易滞后于真实业务	  
5. 知识库与用例质量参差，自动结果必须人工评审闭环  
6. 存量盘活容易，**增量持续沉淀**难（需与需求/开发/测试工具链打通）  
7. 「地图好不好」需要可量化指标（覆盖、准确、复用、回归效率），避免只做展示图

## 5. 数据如何闭环？如何提供服务？如何衡量地图好不好

### 5.1 数据闭环

```
多源输入（历史用例 Excel + 开发知识库）
    → 智能解析（节点识别 / 挂载 / 置信度 / 覆盖矩阵 / 缺口）
    → 人工评审校准（确认 / 调整 / 废弃）
    → 资产沉淀（正式知识库 + 核心回归集 + 版本/生命周期）
    → 价值应用（需求推荐 / 版本回归 / 自动化候选）
    → 结果回流（执行结果、缺陷、变更影响反哺地图与关键词）
```

存量路径：离线导入 → AI 解析 → 批量生成 → 专家评审归档  
增量路径：新需求同步 → 开发关联 → 用例自动挂载 → 结果实时回流  

### 5.2 如何提供服务

| 服务 | 输入 | 输出 |
|---|---|---|
| 地图生成服务 | 领域配置 + 用例 + 知识库 | 可视化地图、挂载结果 |
| 覆盖分析服务 | 地图骨架 + 用例 | 状态/字段/规则矩阵、缺口池 |
| 检索追溯服务 | 关键词/场景/应用/接口/链路/节点+depth | 用例列表或关联子图 |
| 回归优选服务 | 变更节点 / 版本范围 | 核心回归包 |
| 推荐服务 | 需求变更点 | 相关用例 + 缺口提示 |
| 资产管理服务 | 评审结论 | 版本、生命周期、层级视图、导出 |

### 5.3 如何衡量地图好不好

| 维度 | 指标建议 | 说明 |
|---|---|---|
| 覆盖率 Coverage | 状态覆盖率、字段覆盖率、规则覆盖率、节点用例覆盖率 | 矩阵「已覆盖/缺口」占比；P0/P1 缺口清零率 |
| 准确率 Accuracy | 挂载准确率、评审通过率、抽检一致率 | 自动挂载经人工确认正确的比例；低置信度误挂率 |
| 完整率 Completeness | 正式用例依据绑定率、追溯字段完整率 | 入库必填 knowledgeSourceVersion / originalCaseId |
| 复用效率 Reuse | 检索命中率、推荐采纳率、历史用例复用率 | 新需求/回归中复用已有资产的比例 |
| 回归效能 Regression | 回归包用例数下降率、核心路径缺陷拦截率、执行通过率 | 「更少用例、更高防护」 |
| 运营健康度 Health | 已发布资产占比、过期/废弃治理及时率、多层级追溯可用性 | 地图是否可长期运营，而非一次性生成 |

## 6. 整体的功能大图

```text
┌──────────────────────────────────────────────────────────────────────────┐
│                        用例地图平台 · 功能大图                            │
├────────────┬───────────────────────────────┬─────────────────────────────┤
│  输入层    │  历史用例导入 │ 开发知识库接入 │ 领域配置管理               │
├────────────┼───────────────────────────────┼─────────────────────────────┤
│  分析层    │  用例地图生成与挂载 │ 覆盖矩阵分析 │ 缺口识别 │ 置信度计算   │
├────────────┼───────────────────────────────┼─────────────────────────────┤
│  评审层    │  人工评审校准 │ 缺口用例池 │ 核心回归集确认               │
├────────────┼───────────────────────────────┼─────────────────────────────┤
│  资产层    │  正式知识库 │ 场景管理 │ 版本管理 │ 生命周期 │ 层级查看     │
├────────────┼───────────────────────────────┼─────────────────────────────┤
│  查询层    │  关键词/场景/应用/接口/上下游查询 │ 指定节点多层级关联追溯   │
├────────────┼───────────────────────────────┼─────────────────────────────┤
│  应用层    │  新需求推荐 │ 版本回归包 │ 自动化候选 │ 质量运营数据        │
└────────────┴───────────────────────────────┴─────────────────────────────┘

主数据链路：
领域 → 流程节点(上下游) → 测试依据(状态/字段/规则/场景/接口) → 用例资产(版本/生命周期)


---


用例地图不是又一张用例表，而是用代码知识库还原的业务骨架，把散落的历史用例重新挂上去，让测试范围看得见、缺口说得清、回归拉得准；并通过评审闭环把资产变成可检索、可追溯、可度量的测试知识库。
