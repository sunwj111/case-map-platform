# 用例平台功能分析（基于家装报价用例地图样例）

> 依据样例图「用例地图（示例：家装报价功能）」反推。  
> 结论：平台不是平铺用例库，而是以**功能点**为中枢的质量资产图谱。

## 一句话定位

以功能点为核心，把业务逻辑、场景、接口、用例、脚本、数据、缺陷连成可检索、可度量、可编排的质量图谱，并支撑影响分析与精准测试。

---

## 1. 六大能力主轴

| 能力 | 样例图证据 |
|---|---|
| 业务编排 | 业务域→业务流程→核心功能点→关联价值 |
| 资产挂载 | 场景/用例/脚本/数据/缺陷分层关联 |
| 技术映射 | 应用、接口、表、消息、代码模块 |

## 2. 功能模块清单

### 2.1 功能点中枢（核心）
- 以「计算装修报价」为核，左右分别挂业务资产与技术资产
- 展示负责人、更新时间、风险等级、标签（高频/核心链路/金额计算）

### 2.2 业务资产链路
1. **场景管理**：SC-001~005（正常/优惠/边界/幂等/权限）
2. **用例管理**：用例挂场景，含 P0/P1 优先级
3. **自动化脚本**：API / Workflow / UI，状态「可执行」
4. **测试数据模板**：DT 与场景绑定
5. **执行历史**：近 N 次通过/失败与时间

### 2.3 技术映射
- 关联应用（主/从）
- 关联接口清单
- 数据表、消息事件
- 核心代码模块/方法

### 2.4 规则、缺陷与风险
- 业务规则（如金额不可为负）
- 历史缺陷（BUG ID）
- 标签与风险等级

### 2.5 质量总览看板
- 关联用例总数与 P0~P3 分布
- 自动化覆盖率
- 近 30 天缺陷趋势

### 2.6 多维检索
- 按功能点 / 接口 / 场景 / 缺陷 ID / 全局搜索

### 2.7 下游集成
| 消费方 | 用途 |
|---|---|
| 自动化测试平台 | 影响分析、用例推荐、工作流编排 |
| 数据构造平台 | 按模板自动造数 |
| 研发/代码分析 | 代码变更定位回归用例 |
| 质量分析与报告 | 覆盖率与执行趋势 |

## 3. 典型使用场景

1. **新需求测试**：从功能点看场景与缺口，推荐历史用例  
2. **接口变更回归**：按接口反查关联用例与脚本  
3. **代码变更影响分析**：按代码模块拉取核心回归集  
4. **缺陷复盘**：按 BUG 回溯场景/规则/用例是否覆盖不足  
5. **自动化建设**：看未自动化的高优先级用例，优先补脚本  
6. **质量汇报**：直接用功能点总览的覆盖率与缺陷趋势

## 4. 与现有「用例地图平台」建设方案的关系

| 维度 | 样例图（运营态） | 建设方案（生成态） |
|---|---|---|
| 关注点 | 已入库资产如何展示/检索/度量/消费 | 知识库+历史用例如何生成/挂载/评审/沉淀 |
| 中枢 | 功能点 | 领域→流程节点→测试依据→用例资产 |
| 共同点 | 都强调图谱关联、多维查询、回归支撑 | 同左 |

**合在一起才是完整平台：**
1. 生成态：导入知识库与历史用例 → 生成地图 → 评审入库  
2. 运营态：按功能点打开地图 → 检索追溯 → 影响分析 → 下游平台消费

## 5. 建议的平台功能优先级（MVP）

**P0**
- 功能点/流程节点中枢视图
- 场景、用例、接口挂载
- 多维检索与追溯
- 技术映射（至少应用+接口）
- 核心回归集输出

**P1**
- 自动化脚本与执行历史
- 测试数据模板关联
- 覆盖率/自动化率看板
- 缺陷与规则关联

**P2**
- 与造数/自动化/代码分析深度打通
- 变更自动触发影响分析
