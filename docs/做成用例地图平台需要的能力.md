# 做成「用例地图」类平台需要什么能力

> 目标形态：以功能点/流程节点为中枢，串联业务、场景、接口、用例、脚本、数据、缺陷，支持检索、度量、影响分析与下游消费。

---

## 1. 总体结论（先看这个）

要做成样例图那种平台，至少具备 **5 类能力**：

| 能力域 | 一句话 | 缺了会怎样 |
|---|---|---|
| **数据与模型能力** | 有统一的资产模型和关联边 | 只能做列表，做不成图谱 |
| **生产与治理能力** | 能导入/生成/评审/版本/生命周期 | 资产脏、不可信、不可演进 |
| **检索与分析能力** | 多维查询、追溯、影响分析、度量 | 有图不能用，回归仍靠经验 |
| **集成与服务能力** | 对接知识库/用例库/自动化/造数/代码 | 孤立系统，无法闭环 |
| **组织与运营能力** | 有领域负责人、评审机制、验收指标 | 技术建成也运营不起来 |

---

## 2. 产品能力（平台要提供的功能）

### 2.1 P0 必建（没有就不是这类平台）

1. **领域/功能点中枢视图**  
   领域 → 流程/功能点 → 场景/依据 → 用例资产的分层展示  
2. **资产关联挂载**  
   场景、用例、接口、应用、规则、缺陷的双向绑定  
3. **多维检索与追溯**  
   按功能点、场景、接口、应用、缺陷、关键词查询；支持多层级展开  
4. **地图生成与重挂载**  
   历史用例 + 开发知识库 → 自动挂载 + 置信度  
5. **人工评审治理**  
   确认/调整/废弃；低置信度与 AI 缺口必须进评审池  
6. **核心回归集**  
   按节点/功能点输出高价值回归包  
7. **技术映射（最小集）**  
   至少支持：应用 + 接口；建议预留表/消息/代码字段  

### 2.2 P1 增强（样例图里已体现）

8. 自动化脚本关联与可执行状态  
9. 测试数据模板关联  
10. 执行历史回流（近 N 次通过/失败）  
11. 质量总览：覆盖率、自动化率、优先级分布、缺陷趋势  
12. 业务规则与历史缺陷库关联  
13. 风险等级与标签体系  
14. 用例版本管理、生命周期（草稿→评审→发布→废弃）  

### 2.3 P2 深化（规模化运营）

15. 代码变更自动影响分析  
16. 与造数平台、自动化平台、代码分析深度打通  
17. 需求变更触发地图增量更新  
18. 跨领域配置化复制与智能推荐

## 3. 数据与模型能力（底座）

### 3.1 核心对象（节点）

- 领域 Domain  
- 流程节点 / 功能点 FlowNode / Feature  
- 场景 Scene  
- 测试依据 Evidence（状态/字段/规则）  
- 用例 Case  
- 接口 API / 应用 App  
- 脚本 Script / 数据模板 DataTemplate  
- 缺陷 Defect / 规则 Rule  

### 3.2 核心关系（边）

- 归属边（用例→功能点/节点）  
- 依据边（用例→规则/状态/字段）  
- 场景边、系统边（应用/接口）  
- 上下游边、追溯边  
- 版本边、执行关联边  

### 3.3 关键字段能力

- 置信度、评审状态、来源类型（历史/缺口/AI）  
- 版本号、生命周期状态  
- knowledgeSourceVersion、originalCaseId（可追溯）  
- 风险等级、是否核心回归、自动化状态  

没有这套模型，界面再像样例图也只是“画出来”，无法查询和演进。

## 4. 技术能力（怎么实现）

| 技术能力 | 用途 | 建议 |
|---|---|---|
| **图谱存储** | 存节点与边，支持多跳追溯 | 图数据库或「关系库+关联表」起步 |
| **检索引擎** | 关键词/标签/组合过滤 | ES 或等价全文检索 |
| **解析与匹配引擎** | 知识库解析、用例挂载、置信度 | 规则匹配 + LLM 辅助 |
| **任务编排** | 地图生成、批量评审、同步任务 | 异步任务队列 |
| **权限与审计** | 领域隔离、操作留痕 | 评审/发布必须可审计 |
| **API 开放层** | 给自动化/造数/研发调用 | 检索、回归包、影响分析 API |
| **导入导出** | Excel/Markdown/接口同步 | 一期可离线导入 |

## 5. 集成能力（数据从哪来、到哪去）

### 输入侧
- 历史用例平台（Excel/API）  
- 开发知识库（状态机、字段、规则、流程）  
- 可选：接口文档、代码仓库、缺陷系统、需求系统  

### 输出侧
- 自动化测试平台（回归包、推荐用例）  
- 造数平台（数据模板）  
- 研发/代码分析（变更影响）  
- 质量报告（覆盖率与趋势）  

一期可先「离线导入 + 平台内闭环」；二期再做实时同步。

---

## 6. AI 能力（加分但必须可控）

| AI 能力 | 作用 | 约束 |
|---|---|---|
| 知识库结构化抽取 | 从代码/文档抽状态、字段、规则 | 结果需人工校验 |
| 历史用例智能挂载 | 自动推荐节点/场景/依据 | 输出置信度 |
| 缺口用例生成 | 补覆盖盲区 | 不得直接进正式库 |
| 变更影响推荐 | 推荐回归范围 | 人工确认后执行 |
| 智能问答/检索增强 | 降低查找成本 | 需有图谱事实兜底 |

原则：**AI 辅助生产，人工把关入库。**

---

## 7. 组织与运营能力（容易被忽略）

1. **领域 Owner**：每个领域有业务/测试双负责人  
2. **评审机制**：挂载结果、缺口用例、核心回归定期评审  
3. **知识库校准**：开发知识库准确度抽检（你们已识别的挑战）  
4. **增量更新机制**：需求/代码变更后谁触发地图重算  
5. **度量口径统一**：覆盖率、准确率、复用率定义一致  
6. **验收标准**：平台落地、资产归位、缺口共识、回归闭环、查询可用  

---

## 8. 能力成熟度路径（建议分期）

```text
L1 资产盘点：能导入用例/知识库，按节点挂载，可检索
L2 地图治理：有评审、版本、生命周期、覆盖矩阵、缺口池
L3 运营赋能：功能点总览、影响分析、核心回归、自动化关联
L4 智能闭环：变更自动触发、跨平台回流、持续准确率治理
```

对应实施：
- **一期 MVP**：L1 + 部分 L2（导入、生成、评审、入库、检索、回归集）  
- **二期**：补齐 L2/L3（版本、生命周期、技术映射深化、度量看板）  
- **三期**：L4（实时同步、智能影响分析、深度集成）

## 9. 最小可行能力清单（可直接当建设 checklist）

- [ ] 统一数据模型（节点/边/状态/版本）  
- [ ] 历史用例导入 + 知识库接入  
- [ ] 自动挂载 + 置信度 + 人工评审  
- [ ] 四层/功能点中枢视图  
- [ ] 多维查询与多层级追溯  
- [ ] 覆盖矩阵与缺口用例池  
- [ ] 核心回归集输出  
- [ ] 应用/接口技术映射  
- [ ] 对外开放 API（至少查询与回归包）  
- [ ] 覆盖率/挂载准确率度量  
- [ ] 领域 Owner + 评审节奏  

---

## 10. 和当前挑战的对应

| 挑战 | 需要补的能力 |
|---|---|
| 知识库准度待验 | 知识库校验、人工校准、来源版本 |
| 历史复用不足 | 重挂载、改写再生成、评审入库 |
| 变更难以及时同步 | 增量感知、地图重算、任务编排 |
| 地图质量难衡量 | 覆盖率/准确率/完整率指标与看板 |
