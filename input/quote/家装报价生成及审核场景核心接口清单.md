家装报价生成及审核场景核心接口清单

基于 jz_quotation 仓库的代码分析，报价生成及审核涉及两大业务线：报价生成（BOM 报价 / BIM 报价 / 造价单提交）与审核（实勘审核单 / 造价单审核 / 造价审核 PC 页）。下面按业务节点梳理核心接口。

> **技术映射补充（2026-08）**  
> - `关联流程节点` / `关联功能点` 对齐 `configs/quote.json` 的 `flowNodes`，供用例地图「功能点 ↔ 接口」挂载。  
> - `关系类型`：`主接口`（该节点主入口）/ `配套接口`（列表、统计、枚举、接单等支撑）/ `校验接口`（提交前校验）/ `查询接口`。  
> - 一个接口可挂多个节点时用 `；` 分隔；`主归属` 写在最前。  
> - 原「关联业务节点」叙述保留，便于人工理解；机器挂载优先读新增三字段。

四、关键业务节点流转

报价生成:
  管家/设计师发起报价
    ├─ BOM 报价 (/quotation/offer) → submitQuotations → BOM 系统 + 房源/人员 → 保存报价单+造价单
    └─ BIM 报价 (/quotation/bim/offer) → offerQuotations → BOM 物料 + 规则引擎 → 保存报价单+造价单
  全托管 ZO 场景 → 同步生成实勘审核单 (QuotationsReview)

造价单提交审核:
  设计师编辑造价单 → /quotation/submitDesignCost
    → 状态置为"待审核" → 派单 → MQ(ex_design_cost) 通知

造价单审核:
  审核员 → /quotation/confirmDesignCost
    → 校验 AI 评级/改前评级 → 通过(生效+预占库存+延迟作废) / 驳回(企微通知)
    → MQ(ex_design_cost) 通知下游

实勘审核:
  审核员 → /quotation/reviewSubmit
    → 通过/调整通过(重新报价)/驳回
    → MQ(EX_settle_quotation_review) 通知管家端

造价审核 PC 页:
  /costAudit/findList + /costAudit/count → 列表 + 看板
  /costAudit/accept + /costAudit/transform + /costAudit/urgentReview → 接单/转派/催审

实勘审核 PC 页(V2):
  /quotationV2/quotationReviewPage + /quotationV2/count → 列表 + 看板
  /quotationV2/accept + /quotationV2/transform → 接单/转派
> 说明：报价生成有两条并行链路（BOM 报价 QuotationApi#offer 与 BIM 报价 QuotationBimApi#offer），两者最终都会生成报价单（MongoDB）+ 造价单（MySQL）。审核分为造价单审核（confirmDesignCost，核心在 DesignCostServiceImpl.checkDesignCost）与实勘审核单审核（reviewSubmit，核心在 QuotationRPCServiceImpl.reviewSubmit*）。两条审核链路通过 MQ 分别通知不同下游（ex_design_cost 通知造价相关系统，EX_settle_quotation_review 通知管家端）。

### 覆盖说明（对照 quote.json）

| 流程节点 | 本清单是否已挂主接口 | 备注 |
|---|---|---|
| 报价触发与报价单生成 | 是 | offer / bim/offer / kysx / renewal |
| 报价场景识别与价格来源 | 是（多为伴生） | 嵌在报价主接口内，暂无独立 HTTP |
| 参数解析与输入精度 | 是 | checkParamBeforeSubmit；tempSave |
| 物料处理与自动带出 | 是（伴生） | 嵌在 BOM/BIM offer 内 |
| 金额计算与汇总 | 是（伴生） | 嵌在 BOM/BIM offer 计算链路 |
| 造价单生成与明细落库 | 是 | createDesignCost；offer 内落库 |
| 造价提交与审核 | 是 | submit / confirm / costAudit* |
| 实勘审核 | 是 | review* / quotationV2* |
| 申诉审核 | 否 | 本清单未覆盖申诉接口，需另补 |
| 生命周期与外部联动 | 部分 | 主要经 confirmDesignCost / cancelReview 触发；MQ/延迟任务待补 |
| 前端展示与金额明细 | 弱 | 仅枚举/审核详情查询；端上明细接口待补 |
